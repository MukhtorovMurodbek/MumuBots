# 2.2.0: release notes and deploy checklist

## Deploy, in this order

1. **Back up the database.** Step 4 rewrites tables and drops columns.
2. **Variables.** Nothing new is required. Three things are worth checking:
   - For long videos, DownloaderBot needs MTProto: `DBOT_API_ID` / `DBOT_API_HASH` (or
     `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`). Without them, anything over 50 MB is refused.
   - **The data key stays a file on the volume, never a variable.** Railway keeps every deployment's variables, and its breach of 2026-10-21 decrypted customers' variables. `docs/data-protection.md` has the setup, including `railway ssh` to write the key file and `scripts/rotate_data_key.py` to replace a key that ever went through a variable.
   - **`BACKUP_PUBLIC_KEY`** on both services: the public half of your offline key (`python scripts/backup_key.py`). The nightly copy, `/backup` and the erasure notes are encrypted to it.
   - Recommended: `RESERVE_DIR` on the volume the key file is on. See `docs/reserve-copies.md`. The copies there are encrypted to your offline key, so they're safe next to the data key. Without `RESERVE_DIR` only the nightly Telegram copy is made.
   - Not a variable: for DownloaderBot to see the links people post in a group, either make it an admin of that group or turn its privacy mode off in @BotFather (`/setprivacy` → Disable). StickerBot needs neither: it reacts only to commands and to replies to its own messages.
3. **Deploy the image.** All five bots start on the existing database:
   - AnonBot works normally.
   - Sticker, Convert and DownloaderBot seal new usernames from now on.
   - Old usernames stay plain until step 4. Each bot logs a warning about this; that's expected.
4. **Seal the names.** Stop the bots, then:
   ```bash
   python scripts/encrypt_personal_data.py --database-url-env DATABASE_URL --key-file <key file> --dry-run
   ```
   ```bash
   python scripts/encrypt_personal_data.py --database-url-env DATABASE_URL --key-file <key file>
   ```
   - With the key in a password manager rather than a file, use `--key-env DATA_KEY` in place of `--key-file`, after putting the key in that variable for this one command.
   - It refuses while any bot has sent a heartbeat in the last 3 minutes.
   - It stamps `sealed:names:v1`, then VACUUMs.
   - Start the bots again afterwards.
5. **Check.**
   - `/versions` and `/status` show `2.2.0 (<commit>)`. The commit is `RAILWAY_GIT_COMMIT_SHA`, or `FAMILY_BUILD`.
   - `/people` answers. Its history fills itself from the last 90 days of activity within an hour of the start.
6. **Before 2026-12-01: move off `railway.json`.**
   - Railway stops reading it on that date.
   - `.railway/railway.ts` is a draft. Its header has the steps.
   - `railway config migrate` is the safe route, because `railway config apply` deletes anything the file doesn't list, the volume holding the data key included.

## Choosing bots and processes (Railway variables)

The start command stays `python main.py`, from the Dockerfile.

| What you want | Set on the service |
|---|---|
| One bot only | `BOTS=convert`. Names: `sticker`, `convert`, `downloader`, `anon`, `manager` |
| Some bots | `BOTS=sticker,downloader,anon` |
| All in one process (default) | nothing, or `MUMU_PROCESSES=one` |
| A process per bot | `MUMU_PROCESSES=separate` |
| Manager and Convert alone, the rest together | `MUMU_PROCESSES=manager;convert` |
| Any grouping | `MUMU_PROCESSES=manager;convert;sticker,anon`. `;` separates processes; bots that aren't named share one more |

`BOTS` picks which bots run and `MUMU_PROCESSES` splits them into processes, so the two combine.

**Inside one service.** A crashed process is restarted on its own, with backoff, while the others carry on. One deploy still restarts them all.

**As separate Railway services**, give each its own `BOTS`.
- A token may be polled by one service only.
- Each service needs the data key. The simplest way is the same sealed `DATA_KEY` variable on each service. Alternatively, give each its own volume at the same `DATA_KEY_FILE` path, and set `DATA_KEY_INIT` once to write the key there.

**Measured in the image, with fake tokens.**
- Each process loads only its own bots' code: no other bot's sections, and no PDF libraries outside ConvertBot.
- Memory, taken once startup is done:

| Process | Memory |
|---|---|
| ManagerBot | 80 MB |
| ConvertBot | 82 MB (was about 170 MB before the PyMuPDF fixes) |
| Sticker + Downloader + Anon | 89 MB |
| Supervisor | 31 MB |

## What changed

**Reserve copies** (2026-11-03; `docs/reserve-copies.md`)
- The nightly report is followed by the whole database, pinned in the owner's chat.
- With `RESERVE_DIR` on a volume: a copy of that, and a copy of everything but the logs, rewritten within about 2 minutes of a change.
- /deletemydata leaves a note (table, and the volume's journal at once) for 30 days; `scripts/restore_reserve.py` restores and erases those people again.
- 2026-11-09: copies and notes are encrypted to the owner's offline key (`BACKUP_PUBLIC_KEY`), which the bots never hold; volume copies need it. `docs/data-protection.md`.
- LEGAL.md and the privacy texts (en/uz/ru) say copies exist, are for emergencies only, and are never used past 30 days.

**Payments**
- A refunded payment that Telegram delivers again stays refunded.
- If the database drops its answer after a credit went through, the retry finds its own claim. It reports the credit instead of going silent, so the paid conversion starts.
- The "fix this by hand" alert survives a database outage:
  - it's held in memory and sent once the database answers;
  - it also goes straight to the owner on Telegram.
- Free conversions never read or touch the wallet.

**Data key**
- A key problem now switches off only what needs the key:
  - AnonBot answers with a maintenance note;
  - the other bots run without saved state;
  - every bot restarts itself once the key works again.
- Optional startup steps can no longer stop a bot. These are menus, profile, sweeps and the like.
- The update waitlist:
  - forgets a person on /erase;
  - skips people held longer than 7 days (`DEPLOY_WAITLIST_KEEP_DAYS`);
  - is pruned with the rest of the housekeeping.

**Less personal data**
- Usernames and names in Sticker, Convert and DownloaderBot are sealed. This is the new `names` stage of the encryption script. `/whomade` still shows the name.
- Download rows keep only "when", and are deleted after 2 days.
- Activity is written at most once per person per hour.
- The privacy texts (en/uz/ru) say so.
- Merging databases refuses two databases sealed with different keys.

**Resources**
- Memory is measured without the disk cache, which is shown separately in /status.
- Each memory peak is per reporting window.
- Disk reservations, conversion slots and big-file transfers are shared across the bots in a process.
- Big-file transfers:
  - 2 at once, or 1 under a 2 GB memory limit (`BIG_FILES_AT_ONCE`);
  - whoever waits is told so.
- Per-person update handling:
  - holds at most 24 waiting updates per person (`PER_USER_WAITING_MAX`), dropping extras;
  - never drops a successful payment;
  - never queues a checkout behind other updates.
- A crowd is held at Telegram instead of in memory (2026-11-09, `UPDATES_IN_MEMORY_MAX`, default 256 per bot). 2,000 people at once took the five bots from 94 to 399 MB, which stayed after they had gone; now 170 MB. `docs/memory-and-rust.md`.
- GIF/WebP/APNG is only offered when the video is short enough to finish. A conversion that is too long is refused before any charge.

**Downloader**
- Instagram posts no longer send each photo twice. The provider returns two links per photo, and only one is kept now.
- Video downloads through yt-dlp:
  - The image now ships Deno (`yt-dlp[default,deno]`): some sites need a JavaScript runtime.
  - yt-dlp is tried before cobalt.
  - A format picker fits the best H.264 + AAC under the size budget. Downloads take 4 fragments at once (`DBOT_YTDLP_FRAGMENTS`).
  - The cap is 3 hours (`DBOT_MAX_DURATION_SECONDS`).
  - Big videos go over MTProto as streamable video.
- The file-id store is compact (2026-11-09; `sent_files.py`): a 16-byte key and the ids as bytes, 216 bytes a row instead of 376 at a million rows, an index a third the size. One row per post however it was shared (/p/ and /reel/ of one Instagram code, an X status under any account), no write when a row is already marked used today, and a short in-process memory for a post many people send at once. The 2.1 table is a cache and is made anew on the first start: each post is downloaded once more.
- Each person's last delivery is kept for 10 minutes (it was 5 in 2.1). "Get compressed/uncompressed", and merging, reuse it instead of downloading again (`DBOT_CACHE_PER_USER`, `DBOT_CACHE_SECONDS`).
- A quality picker for videos that come in several sizes: each height with its size, ✅ free or ⚡ paid (large files), and a button to ConvertBot for MP3, trimming and the rest. Nothing is asked when there is only one choice.
- Group chats: added to a group, the bot downloads the links posted there and sends them as videos. `/settings` in the group picks the sites, the quality cap, video or file, the credit line, and whether only admins may change them. The bot needs to be an admin of the group (or have privacy mode off in @BotFather) to see the links. It reads the group's other messages only to find links: nobody there counts as a user unless the bot downloads something for them, the per-person flood limit does not count group chatter, and a progress message is edited where it is instead of being sent again under every reply.
- Channels (2026-11-07): added to a channel as an admin, the bot puts the video or photos of a post's link into that post: the post's text becomes the caption, Telegram marks it edited, and nobody is notified twice. Several files, or no right to edit, and it posts them anew (silently) and deletes the link post; that can be turned off. The admin who adds the bot gets the settings in a private chat (sites, quality, video or file, credit line, posting anew), any admin later with `/channels`. Files over the free size are not sent in channels, a failed download says nothing there, and a channel's links use nobody's allowance. Needs the admin right "Edit messages of others" (and "Post messages" and "Delete messages of others" for posting anew). Code in `channels.py`.

**StickerBot**
- Every sticker added gets a short reply of its own ("✅ Added as #4 with 😭"). Several pictures sent quickly each get theirs, and each of those replies also counts the run: "⏳ 5/7" while more are waiting, then "✅ 7/7", or "⚠️ 7/7 — 1 not added" (2.1.4 showed the same count on its status message).
- Telegram's limits and hiccups (2.1.5, from production's errors of 2026-10-29 to 11-04): a picture that meets the flood limit ("Retry in 10 seconds") is added after the wait instead of being lost, up to 3 tries and waits of up to 30 seconds; fetching a picture, clip or WhatsApp pack, and reading the pack back, are tried again after a timeout; a fetch that still fails is a short note instead of the crash reply; a new pack whose name Telegram refuses ("Shortname_occupy_failed") gets another. Only the person who sent the pictures waits. `sticker_ops.py`.
- Reply to a sticker, to the picture it was made from, or to the bot's reply, with an emoji to change that sticker's emoji (`/emoji 😎` does the same; `/emoji` alone, as a reply, asks for the emoji). In a group the bot only sees replies to its own messages, so there a member's sticker is retagged with `/emoji 😎` as a reply, and an emoji alone works as a reply to the bot's "Added" message.
- Nothing asks for `/done` any more: every sticker is saved as it is added, the first sticker's reply carries the pack's link, and each reply names the pack. `/done` still works (it closes the pack and sums it up). Text that is not an emoji is ignored, and `/start`, `/mypacks`, a rename and the rest work without closing the pack.
- The donation reminder is counted at the first sticker of a session instead of at `/done`.
- Packs are private (default) or public (a button in `/mypacks`).
- Group chats: `/packs` lists the public packs of the group's members, reply to media with `/add <number>` to add it, `/emoji` to retag. Only the people who use it there count as its users. A private pack answers "you don't have access"; its co-edit link, posted in the group, lets people in.
- Co-edit links have limits: at most 10 co-editors (3/5/10/20/50) and valid for a week (a day, a week, a month or no limit), both set on the co-edit screen. Links made before 2.2.0 get those defaults from the upgrade, so they stop letting new people in a week after it. The owner can also invite people by @username (they get access the next time they use the bot), see everybody who can add, and remove anyone. Packs shared with you show in `/mypacks` marked 👥.
- A co-editor who is removed stops being able to add, within a minute even in an open pack.
- A sticker sent that is already in the pack is asked about instead of removed at once (2.1 removed it, whoever sent it). The owner gets "➕ Add again" and "🗑 Remove it" (removing the last sticker deletes the pack, so that asks once more). A co-editor gets "➕ Add again" and "✖ Don't add", unless the owner switches on "🗑 Co-editors can delete" on the co-edit screen (off by default, also for links made before; then they get "Remove it" too, but never for the last sticker). Nothing is deleted from a group: `/add` on such a sticker offers only to add it again.
- Fixed: the last step of deleting a pack did not check the owner (a missing `await`).
- Fixed: `/mypacks` kept the old name of a pack renamed outside the bot. It is shown from what is stored, then Telegram is asked for the current titles (up to 50 packs, 4 seconds); changed ones are saved and the list is corrected in place.

**Every public bot**
- Error messages are three short lines: what happened, "Anonymous report is saved", and the code.
- Shorter texts (owner's request of 2026-10-31): replies, prompts, errors and the help pages say what happened and what to do next, without the reasons around it. In all three languages. /privacy, /terms, /deletemydata and the payment texts too: every fact and time limit is kept (LEGAL.md has the full text), only the wording is shorter.

**AnonBot**
- A "✖️ Cancel" button under the line a link tap opens with. It turns that line into "Cancelled." at once and removes the empty conversation behind it, so the next message is not sent to that person by mistake. It comes off once the first message has gone.

**The nightly report**
- Called the nightly report again: `/nightly` is its name, `/problems` still works.
- It starts with the unique users: all bots, all time, and the last 24 hours, each with its change since the previous report.

**Unique users over time (new: `/people` in ManagerBot)**
- Usage:
  - `/people`: the last 7, 30 and 90 days, per bot and across all bots, then the past months;
  - `/people 14`, `/people 2026-09`, `/people 2026-09-01 2026-09-15`: any other stretch.
- Counting, with no ids kept for it:
  - any stretch inside the last 90 days is counted exactly, live, from the activity the bots
    already keep for 90 days;
  - before that, only each whole day's and month's count is kept (`family.people_counts`),
    as plain numbers that say nothing about who;
  - so there is no "since the start" figure: counting people across years would need
    something that remembers who was counted.
- `/users` is unchanged.

**Operations**
- Versions:
  - the version label `2.2.0 (<commit>)` is in /status, /versions and the heartbeats;
  - `VERSION` still gates commands.
- An unreachable database at startup is waited for instead of exiting:
  - an error is logged every 5 minutes;
  - a wrong password, or a host that never resolves, still ends the run at once.
- `MUMU_PROCESSES` takes groups (see the table above). It used to be "one" or "separate" only.
- ConvertBot no longer imports PyMuPDF at startup just to see whether text recognition can run.
- Dependencies:
  - `PyMuPDF` is held below 2. 2.0 came out on 2026-10-19 and loads onnxruntime, numpy and pymupdf4llm on every import, which is about 90 MB per document conversion. 1.28.2 converts everything ConvertBot offers. The image went from 1.68 GB to 1.46 GB.
  - python-telegram-bot, psycopg, Pillow, pillow-heif, Telethon and httpx are held below their next major version, so a build weeks from now can't pull in a breaking release. Telethon 2 is a rewrite.
  - yt-dlp is left free to update, since the sites it reads change often.
  - `APScheduler>=3.11,<3.12`.
- The data key can come from a `DATA_KEY` variable instead of a file, for local runs. On Railway it is warned against at every start, and `/status` flags it: see `docs/data-protection.md`.
  - `main.py` copies it to a private file in `/dev/shm` for the run, and takes it out of the environment so no other program inherits it.
  - The encryption script takes `--key-env NAME` as an alternative to `--key-file`.
- **Backups encrypted to an offline key** (`BACKUP_PUBLIC_KEY`, standard `age` format). The bots hold only the public half, so the volume (which also holds the data key), leaked variables or a forwarded Telegram file give nothing away. `scripts/restore_reserve.py --backup-key-file` opens them.
- **`scripts/rotate_data_key.py`** replaces the data key: every seal and pseudonym re-keyed in one transaction, nothing readable written, the bots' own checks run under the new key before COMMIT.
- `db_merge` checks that both databases share the key and have their names sealed before it touches either one.
- tini is PID 1, so signals reach the bots and zombie processes are cleaned up.
- In one process:
  - a bot's own `.env` can no longer change the others' settings when it restarts alone;
  - if the bot reporting memory stops for good, another takes over.

## Known limits

- Memory-report handover works in one process only. In separate processes, if ManagerBot stops for good, memory reports stop with it.
- `family.problem_reports.username` stays plain, as the problem-report notice tells people.
- ConvertBot still loads PyMuPDF on the first document someone sends, to count its pages. With 1.28 that's a modest, one-time cost.
- Before moving to PyMuPDF 2, check whether its import can skip pymupdf4llm. Until then, the cap stays.
